## 第 A 课：稀疏向量空间——能算了，但不懂「近」

### 概念

- **One-Hot**：词表有 \(V\) 个词，第 \(i\) 个词就是长度 \(V\) 的向量，只有第 \(i\) 维是 1。  
- 任意两个不同词的 One-Hot 点积必为 0 → **余弦相似度恒为 0**。  
  「国王」和「王后」在几何上与「国王」和「电脑」一样远——模型分得出「是谁」，分不出「像不像」。  
- **TF-IDF**：给「在少数文档里很突出」的词更高权重，利于检索/分类；**它不负责把近义词拉到一起**。

### 核心代码（摘自 `05_sparse_vsm_lab.py`）

```python
vocab = ["国王", "王后", "电脑", "计算机", "苹果", "香蕉"]
eye = np.eye(len(vocab))  # One-Hot 矩阵：每行一词

# 任意两词余弦
va, vb = eye[stoi["国王"]], eye[stoi["王后"]]
cos = float(np.dot(va, vb) / (np.linalg.norm(va) * np.linalg.norm(vb)))
# → 不同词必为 0

# TF-IDF 只是换权重，仍是稀疏词袋
tfidf = TfidfVectorizer()
x_tfidf = tfidf.fit_transform([" ".join(jieba.lcut(d)) for d in docs])
```

### 这意味着什么

1. 矩阵几乎全是 0——**稀疏**是肉眼可见的。  
2. 近义词与无关词在 One-Hot 里**无法区分远近**。  
3. 「我买了一台电脑」vs「我购买了一台计算机」即便意思近，TF-IDF 也只有 **0.301**，因为用词不完全重叠。  
→ **下一代必须让「意思近」变成「向量近」，并且最好还能利用词序。**

## 第 B 课：N-gram——把「谁在谁后面」找回来

### 概念

词袋（Bag-of-Words）只看词集合，不看顺序，所以：

> 「狗咬人」和「人咬狗」计数向量可以完全一样。

N-gram 语言模型假设：当前词只依赖前 \(N-1\) 个词。例如 trigram：

\[
P(w_i \mid w_{i-2}, w_{i-1})
\approx
\frac{c(w_{i-2},w_{i-1},w_i)+\alpha}{c(w_{i-2},w_{i-1})+\alpha |V|}
\]

（本实验用加性平滑 \(\alpha=0.5\)。）句子越符合训练中见过的局部顺序，log 概率越高、困惑度（PPL）越低。

### 核心代码（摘自 `06_ngram_order_lab.py`）

```python
# 词袋：顺序丢失
s1, s2 = "狗咬人", "人咬狗"
x = CountVectorizer(...).fit_transform([s1, s2])
# → 两行计数相同，余弦 = 1

# Trigram + 平滑：累加 log P
def log_prob(self, text):
    toks = ["<s>"] * (n - 1) + jieba.lcut(text) + ["</s>"]
    total = 0.0
    for i in range(n - 1, len(toks)):
        ng = tuple(toks[i - n + 1 : i + 1])
        ctx = ng[:-1]
        total += math.log(
            (self.ngram_counts[ng] + alpha)
            / (self.context_counts[ctx] + alpha * len(self.vocab))
        )
    return total
# perplexity = exp(-logP / 词数)
```

### 这意味着什么

1. 词袋对调序标题 **余弦 = 1.0**——语义天差地别，表示却相同。  
2. 通顺句 PPL≈**2.4**，乱序句 PPL≈**38–61**：N-gram **真的在用局部词序打分**。  
3. \(N=5\) 理论组合上亿、实际只见到几十种 → **数据稀疏 / 组合爆炸**。  
4. 词仍是离散符号，没有「国王≈王后」这种连续几何。  
→ **下一代：用稠密向量共享语义。**

## 第 C 课：Word2Vec——近义词终于靠拢，但「苹果」只有一个点

### 概念

Skip-Gram：用**中心词**去预测窗口里的**上下文词**（再加负采样）。训练压力会把「常出现在相似上下文」的词拉近。

相对 One-Hot：维度从 \(V\) 降到几十维，且 **\(\cos(\text{国王},\text{王后})\) 不再被迫为 0**。

致命限制：**静态查表**——`emb["苹果"]` 与当前句子无关。水果义与公司义共用同一个向量。

### 核心代码（摘自 `07_static_embedding_lab.py`）

```python
# 正样本：中心 center 预测上下文 pos；负样本从 noise 分布抽
vc = w_in[center]
pp = sigmoid(dot(vc, w_out[pos]))
loss += -log(pp)
# 负采样
pn = sigmoid(dot(vc, w_out[neg_id]))
loss += -log(1 - pn)
# 反向更新 w_in / w_out …

# 静态之痛：查表与句子无关
v_static = emb[stoi["苹果"]]
# vec(苹果|水果句) is vec(苹果|公司句) → 永远 True
```

```
  vec(苹果|句1) is vec(苹果|句2) ?  True  (永远 True)
```

### 这意味着什么

1. loss 从 **2.67 → 0.99**：模型在学「谁和谁常一起出现」。  
2. `cos(国王,王后)=0.575`，而 One-Hot 是 **0**——**语义几何出现了**。  
3. `国王–香蕉` 只有 **0.195**，低于多数相关对（演示用小语料，不必苛求完美类比）。  
4. 无论句1句2，`苹果` 都是同一 8 维片段——**一词多义未解**。  
→ **下一代：向量必须是上下文的函数。**

## 第 D 课：上下文表示——让「苹果」随句子变身（ELMo 风格类比）

### 概念

原版 **ELMo**：大规模双向语言模型，取各层隐状态组合成**随位置/句子变化**的词表示。

本课不做原版权重，而做**同构直觉**：

1. **CBOW 式上下文编码器**：中心词的表示 = `MLP(mean(邻居嵌入))`，邻居不同 → 向量不同。  
2. **迷你 BiLSTM-LM**：位置隐状态也会随整句变化。

对照表：

| 原版 ELMo | 本课实验 |
|---|---|
| 大规模双向 LSTM LM | 邻居聚合编码器 + 迷你 BiLSTM |
| 层组合隐状态 | `context_vector` / LSTM hidden |
| 一词多义 | 水果句 vs 公司句的「苹果」余弦 &lt; 1 |

### 核心代码（摘自 `08_contextual_bilstm_lab.py`）

```python
class ContextEncoder(nn.Module):
    def context_vector(self, neighbor_ids):
        # 不含中心词本身：只看左右邻居
        e = self.emb(neighbor_ids) * mask
        mean = e.sum(dim=1) / mask.sum(dim=1).clamp(min=1)
        return self.mlp(mean)   # ← 上下文向量
    def forward(self, neighbor_ids):
        ctx = self.context_vector(neighbor_ids)
        return self.out(ctx), ctx   # 训练目标：用 ctx 预测中心词

# 推理时
v_fruit   = ctx_vec_for_word(enc, "我 今天 中午 吃了 一个 苹果", "苹果")
v_company = ctx_vec_for_word(enc, "苹果 公司 发布了 新款 手机", "苹果")
# 静态表：emb["苹果"] 与自身余弦恒为 1
# 上下文：cos(v_fruit, v_company) < 1
```

### 刚才真实跑出的关键数字

```

句2: 苹果 公司 发布了 新款 手机
```

### 这意味着什么

1. 上下文编码器 loss **0.62 → 0.0002**：邻居模式足以预测中心词。  
2. 静态表余弦 **= 1.000**（两句共用一点）；上下文余弦 **= 0.716**——**同一「苹果」已经分开**。  
3. 前 8 维数值也不同（注意第 2、4、6 维符号/幅度差异）。  
4. BiLSTM 隐状态余弦 **0.912 &lt; 1**：同构地说明「位置表示随句变」；原版 ELMo 把这件事做到大规模预训练。  
→ **更强的全局、并行上下文建模，就是第 2 章 Transformer。**

## 自测题（先闭卷想，再对答案）

1. 为什么 One-Hot 下「电脑」和「计算机」的余弦一定是 0？这暴露了什么需求？  
2. 词袋为何分不清「狗咬人 / 人咬狗」？本课用什么指标证明 N-gram 在用词序？  
3. Word2Vec 相对 One-Hot 赢在哪里？它在「苹果」例子上仍失败的一句表述是什么？  
4. 上下文向量与静态查表的本质差别是什么？本课测到的两个关键余弦各是多少？  
5. 用一句话把 A→B→C→D 的动机串起来。

<details>
<summary>参考答案</summary>

1. 不同标准基向量点积为 0；需要能表达「语义相近」。  
2. 只保留词多重集合、丢掉顺序；通顺句 PPL≈2.4、乱序≈38–61。  
3. 近义词可靠近（如国王–王后 0.575）；失败点：**一词一向量 / 查表与句子无关**。  
4. 上下文向量是邻居（或整句）的函数；静态 cos≡1.000，水果/公司上下文 cos≈0.716。  
5. 能量化 → 能按序预测 → 能共享语义几何 → 能随上下文变身。
